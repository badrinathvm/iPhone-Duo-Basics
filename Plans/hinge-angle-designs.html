When there's no hinge

Most people (and every current simulator) have no hinge, so state.current is nil. Whatever you pick needs to look intentional here. Two treatments:

Empty state
No hinge on this deviceThe hinge angle appears here on a foldable iPhone.
Demo mode (optional)
Demo modeNo hinge found. Drag to explore the design with a simulated angle.

Recommendation

Build A first. It stays closest to your screenshot, needs no framework beyond SwiftUI, and its folding panels give the "3D model" feel the catalog already promises.

  • Move D's posture strip to the Hinge History screen, where history belongs.
  • Keep F as a later upgrade once A is solid.
  • C and E are worth borrowing from (peak/low markers, sparkline) rather than building whole.
// fold = 180 - angleDegrees   (sign to confirm in a preview)
HStack(spacing: 0) {
  panel("A").rotation3DEffect(.degrees(fold / 2), axis: (0, 1, 0),
                              anchor: .trailing, perspective: 0.6)
  panel("B").rotation3DEffect(.degrees(-fold / 2), axis: (0, 1, 0),
                              anchor: .leading, perspective: 0.6)
}

What changes in the project

  • View/HingeAngleView.swift
    Becomes the screen: composes the pieces below and handles the nil reading state.
  • View/HingeFoldTile.swiftView/HingeArcGauge.swiftView/HingePostureChips.swift
    New views for option A. HingeBadge stays for the sidebar header.
  • Utils/Hinge+Display.swift
    Adds angleRadians, a clamped progress (angle ÷ 180) and a radians string. Reuses the existing HingeStatus title, symbol and colour.
  • #Preview blocks
    A slider-driven harness that builds HingeReading directly, so previews work with no foldable and without the 27.1 SDK.
  • Animation
    .smooth on the reading so tile, gauge and chips move together. Reduce Motion turns off the 3D swing.
  • Domain/Actions/Data/
    No changes.

Assumptions to confirm

  • The hinge range is 0–180°, as in your screenshot. I'll check the real DeviceHinge docs on the 27.1 SDK and clamp to the true range.
  • The posture cut-offs in this page (closed under 10°, fully open from 170°) are placeholders. The app uses the SDK's own status.
  • The rotation3DEffect signs and perspective value need confirming in an Xcode preview. The code above is a sketch, not compiled.
  • Should the screen offer demo mode when there's no hinge, or just the empty state?
  • These mockups are HTML/CSS/SVG design targets, so SwiftUI rendering will differ in detail.
